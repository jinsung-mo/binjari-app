# BINJARI 요구사항 명세

현재 저장소의 앱과 서버 구현을 기준으로 정리한 기능 명세입니다. 화면·API·처리 로직을 함께 확인할 수 있도록 요구사항마다 코드 위치를 연결했습니다.

## 서비스 범위

| 구분 | 내용 |
| --- | --- |
| 운전자 | 지도에서 주차장을 찾고, 주차면 현황과 시간대별 점유율을 조회 |
| 관리자 | 분석 시작·중지, 주차장 정보·영상 소스·주차면 좌표 관리 |
| 분석 서버 | 영상 프레임 추론, 주차면별 상태 판정, 이력 저장, 조회 API 제공 |
| 기본 분석 대상 | 55호관 20면, 도서관 36면(코드에 정의된 기본 좌표 기준) |

## 품질·운영 요구사항

| ID | 요구사항 | 구현 방식 |
| --- | --- | --- |
| NFR-01 | 불필요한 모델 추론을 줄인다. | 기본 설정에서 5프레임 중 1프레임만 추론한다. 이는 **추론 대상 프레임 수**를 약 80% 줄이는 설정이며 전체 처리 시간의 감소율을 뜻하지 않는다. [`app_v1.py`](../app_v1.py#L695-L704) |
| NFR-02 | 순간적인 탐지 누락이 즉시 빈자리 안내로 이어지지 않도록 한다. | 일반 주차면은 최근 10개 결과의 시간 가중 필터와 점유 5회·빈자리 8회 상태 전이 기준을 사용한다. [`app_v1.py`](../app_v1.py#L1225-L1405) |
| NFR-03 | 서로 다른 주차장의 동일한 주차면 ID를 구분한다. | 현재 상태 테이블의 기본키를 `(parking_lot, id)`로 정의한다. [`app_v1.py`](../app_v1.py#L346-L357) |
| NFR-04 | 운영 기능에 대한 접근을 제한한다. | 관리자 API는 `X-Admin-Token`을 확인하고 일치하지 않으면 `401`을 반환한다. [`app_v1.py`](../app_v1.py#L1505-L1520) |
| NFR-05 | 관측하지 않은 혼잡도를 실제 측정값처럼 표시하지 않는다. | 통계 API는 기록이 없는 시간대를 `has_data=false`로 표시하고 추천 대상에서 제외한다. [`app_v1.py`](../app_v1.py#L1624-L1659) |

## 실행 전제와 범위

- 실제 YOLO 추론에는 프로젝트용 모델 가중치가 필요합니다. 가중치는 이 저장소에 포함되어 있지 않습니다.
- 기본 실행 영상으로 도서관 영상 `videos/library2.mp4`가 포함되어 있습니다. 다른 영상·스트림은 서버 설정에 맞게 지정해야 합니다.
- Google Maps 화면에는 각 플랫폼의 API 키가 필요합니다.
- 추천 기능은 저장된 점유율의 시간대별 비교이며 미래 혼잡도를 학습해 예측하는 별도 모델은 아닙니다.

엔드포인트별 요청·응답은 [API 명세](API.md)에 정리했습니다.
